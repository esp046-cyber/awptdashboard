What is SCADA?

SCADA (Supervisory Control and Data Acquisition) is a system architecture for monitoring and controlling industrial processes remotely and in real time. It is the central nervous system of any modern water utility.

🛰️

Supervisory

High-level oversight and command capability. Operators see the entire plant on graphical HMI screens and can issue set-point changes, start/stop commands, and acknowledge alarms.

🎛️

Control

PLCs and RTUs execute real-time control logic — PID loops, interlocks, sequential logic — independently of the SCADA server for deterministic safety.

📊

Data Acquisition

Continuous collection of process values, alarm states, and events from field instruments. All data is time-stamped, stored in historians, and available for reports and analytics.

How AWPT Uses SCADA

Alkhorayef Water & Power Technologies (AWPT) deploys SCADA across its EPC and O&M contracts, enabling real-time control of water treatment, wastewater, desalination, and distribution networks throughout Saudi Arabia and the GCC.

Water Treatment Plants (WTP)

AWPT SCADA at WTPs monitors and controls the complete treatment train from raw water intake to potable water delivery. Key automated processes include:

  • ▸Coagulation & Flocculation: Auto-dosing of alum and polymer based on turbidity feedback
  • ▸Sedimentation: Level monitoring, sludge blanket sensors, automated sludge withdrawal
  • ▸Filtration: Filter-to-waste sequencing, differential pressure monitoring, auto-backwash
  • ▸Chlorination: Residual chlorine dosing loop (PID control), contact time monitoring
  • ▸pH Adjustment: Lime/CO₂ dosing with pH feedback loop
  • ▸Fluoridation: Accurate metering pump control per NWC standards

Wastewater Treatment Plants (WWTP)

SCADA at AWWTPs manages complex biological and physical-chemical treatment processes with tight regulatory effluent limits set by the Saudi Ministry of Environment.

Cybersecurity Best Practices CRITICAL

🔒 Saudi Context: NCA (National Cybersecurity Authority) and OTCC (Operational Technology Cybersecurity Controls) framework mandates specific security controls for critical water infrastructure in the Kingdom.
🔒 Network Segmentation (Defense in Depth) ▼

▸ Separate OT network from IT network with industrial DMZ

▸ No direct internet connectivity from SCADA servers

▸ IDMZ (Industrial DMZ) with data diodes for historian replication

▸ Purdue Model / IEC 62443 zone and conduit model

▸ Firewall rules: whitelist-only, minimal open ports

👤 Access Control & Authentication ▼

▸ Role-based access control (View / Operate / Engineer / Admin)

▸ MFA for remote access via VPN

▸ No shared accounts — individual user IDs for full audit trail

▸ Password policy per NCSC guidelines (min 12 chars, complexity)

▸ Privileged Access Management (PAM) for admin accounts

🛡️ Patch Management & Hardening ▼

▸ OS patching schedule — test in staging before production

▸ Disable unused services, ports, and protocols

▸ Application whitelisting on SCADA servers

▸ USB port control / disabling on OT workstations

▸ Antivirus with OT-aware signatures (Claroty, Dragos, Nozomi)

🔄 Backup & Disaster Recovery ▼

▸ Daily automated backups of SCADA project files, PLC programs, historian DB

▸ Offsite backup storage (air-gapped)

▸ RTO (Recovery Time Objective) < 4 hours for water critical systems

▸ Annual DR drill to test restoration procedures

Redundancy & High-Availability Design

Server Redundancy

  • ▸ Primary + Hot-standby SCADA server (automatic failover <1s)
  • ▸ Redundant network switches (ring topology, STP/RSTP)
  • ▸ RAID storage for historian database
  • ▸ UPS on all OT servers (minimum 30 min autonomy)
  • ▸ Diesel generator backup for control room

Communication Redundancy

  • ▸ Dual fiber paths (ring + star to RTUs)
  • ▸ Primary fiber + backup 4G/LTE for remote sites
  • ▸ RTU store-and-forward: holds data locally if comms lost, uploads on reconnect
  • ▸ Heartbeat watchdog — SCADA detects comms loss within 60s

PLC/Field Redundancy

  • ▸ Redundant CPU for main plant PLC (hot standby, sync'd)
  • ▸ Redundant 24VDC power supplies in panels
  • ▸ Dual I/O for critical measurements (voting logic 2oo3 for SIS)
  • ▸ Pump lead-lag-standby: automatic switchover on fault

Alarm Configuration Best Practices

CRITICAL (Priority 1)
Immediate threat to safety or environment. Response: <5 min. Examples: pump station overflow, Cl₂ dosing failure, treated water quality limit breach.
HIGH (Priority 2)
Requires prompt action to prevent escalation. Response: <30 min. Examples: high turbidity, instrument calibration due, filter DP high.
MEDIUM (Priority 3)
Abnormal condition, corrective action within shift. Examples: pump runtime equalization due, VFD minor fault, minor flow deviation.
LOW (Priority 4)
Informational — no immediate action needed. Examples: mode changes, daily reports generated, scheduled maintenance reminders.
⚠️ ISA-18.2 Target: Alarm rate should not exceed 1 alarm per operator per 10 minutes in steady state. More than 10 alarms/10 min is considered a "flood." Alarm rationalization workshops are essential in AWPT projects.

HMI Screen Design Best Practices

  • ▸ Use gray as the neutral background (not white/black) — ISA-101 guideline. Colors reserved for alarm states only.
  • ▸ No 3D effects or animated graphics in steady state — distracts operators from genuine alarms.
  • ▸ Faceplates for every field device — consistent, pop-up detail view per instrument.
  • ▸ Critical values displayed in large, readable digits — visible from 3m away.
  • ▸ Navigation hierarchy: Overview → Area → Unit → Equipment. Max 3 clicks to any faceplate.
  • ▸ Situational awareness: Always show plant status summary on every screen header.

Troubleshooting Common Issues

📡 Communication Loss to RTU/PLC ▼

1. Check SCADA server communication log for error code

2. Ping the RTU/PLC IP from the SCADA server

3. Check network switch port status (link, speed, duplex)

4. Check fiber / cable continuity if ping fails

5. Verify RTU/PLC power supply — check panel UPS

6. If remote site: verify 4G SIM status with carrier

7. If all fail: dispatch technician for site visit

🔔 False / Nuisance Alarms ▼

Root Causes: Incorrect alarm limits, noisy analog signal, instrument calibration drift, alarm shelving not used during maintenance

Fixes: Run alarm rationalization. Add deadband (5% typical). Check instrument calibration. Implement maintenance mode suppression. Review and adjust alarm setpoints using process historian data.

🖥️ HMI Freezes / Slow Response ▼

1. Check SCADA server CPU and RAM utilization

2. Check disk space on historian server (may be full)

3. Review SCADA error log for memory leaks

4. Check network utilization — may be saturation event

5. Restart SCADA gateway service (not server) if safe

6. Escalate to vendor support if recurring

📊 Historian Data Gaps ▼

Cause A: Communication outage — RTU store-and-forward should backfill. Verify backfill is configured and ran after comms restored.

Cause B: Historian disk full — archives not created. Check archiver service health. Clean old archives per retention policy.

Cause C: Tag scan class set too slow. Review tag scan classes in SCADA configuration.

RTU vs PLC — Deep Dive

RTU (Remote Terminal Unit)
  • ▸ Designed for wide-area, harsh environments
  • ▸ Ruggedized for outdoor/buried installation
  • ▸ WAN communication protocols: DNP3, IEC 60870-5
  • ▸ Store-and-forward data buffering
  • ▸ Lower I/O count, simpler logic
  • ▸ Used at unmanned remote pumping stations, booster stations
PLC (Programmable Logic Controller)
  • ▸ High-speed deterministic real-time control
  • ▸ Rich I/O options, modular expansion
  • ▸ Complex ladder/function block/structured text programming
  • ▸ LAN protocols: OPC-UA, Modbus TCP, PROFINET
  • ▸ Used at main plant control panels, process areas
  • ▸ Examples: Siemens S7-1500, Allen Bradley ControlLogix, Schneider M580

HMI System Design

Modern HMI design follows ISA-101 High Performance HMI standard. Key principles:

▸ Situational Awareness: Operators must grasp the plant state in under 5 seconds from any screen
▸ Color Coding: Gray = normal, Yellow = warning, Red = alarm, Green = OK/running, Blue = info/manual
▸ Screen Hierarchy: Level 1 (overview) → Level 2 (area) → Level 3 (unit) → Level 4 (faceplate/trend)
▸ No decoration: Every pixel serves a purpose. No logos, animations, or 3D effects that don't convey process state
▸ Consistency: All flow goes left to right. All temperature scales the same direction. No surprises.
▸ Acknowledgment: Critical alarms require explicit operator acknowledgment — automated clearance is not acceptable
⚠️ Poor HMI design is a documented contributor to major industrial incidents. AWPT engineers should complete ISA-101 training before designing plant HMI screens.
